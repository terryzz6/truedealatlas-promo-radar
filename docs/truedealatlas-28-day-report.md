# TrueDealAtlas 28 天数据报告：Codex 执行说明

> 把本文件原样交给负责报数的 Codex。它必须按本文执行，不需要自行补充分析。

## 任务

每 28 天为 `truedealatlas.com` 生成一次只读数据报告。只读取 Google Search Console（GSC）、Google Analytics 4（GA4）和仓库中的已发布文章记录，不分析增长原因，不调整网站，不发布内容。

本任务与 GitHub Actions 的日更发布任务彼此独立。不要运行或修改日更队列。

## 固定配置

- 时区：`America/Los_Angeles`
- 周期起点：`2026-09-29`
- 第 1 轮内容周期：`2026-09-29` 至 `2026-10-26`
- 第 1 次报告日：`2026-10-27`
- 后续报告日：从 `2026-10-27` 起每隔 28 天
- GSC 站点：只接受与 `truedealatlas.com` 精确对应的资源，例如 `sc-domain:truedealatlas.com` 或已验证的 `https://truedealatlas.com/`
- 主关键词（本轮锁定）：`old navy coupon`
- 对标站（本轮锁定）：`rankandstyle.com`、`retailmenot.com`、`capitaloneshopping.com`

关键词和对标站只作为周期标识，不需要查询它们的数据，也不得在本任务中更换。

## 开始前

1. 进入 TrueDealAtlas 仓库，依次读取 `AGENTS.md`、`.ilang/site.ilang` 和 `README.md`。
2. 找到机主提供的、已经连接 GSC 的 Python 脚本。先阅读脚本说明或执行其 `--help`，确认它支持哪些只读查询；不要猜测文件名、参数或返回字段。
3. 不得修改、删除或输出 OAuth 凭据、服务账号密钥、刷新令牌和浏览器登录信息。
4. 让脚本列出或确认可访问的 GSC 资源。只查询与 `truedealatlas.com` 精确匹配的资源；有多个疑似资源且无法确定时，停止该项并写“读不到”。
5. 记录每次查询使用的资源名、指标名、日期范围和时区，便于复核。

如果脚本不能完成某项查询，可以使用当前电脑上已经授权的官方 GSC 或 GA4 界面读取该项。不得绕过登录、验证码或访问控制。

## 周期计算

设本次报告日为 `R`，所有日期按洛杉矶日期计算。

- 只有当 `R = 2026-09-29 + 28 × N 天` 且 `N >= 1` 时，才生成第 `N` 轮正式报告。
- 第 `N` 轮文章周期为：`2026-09-29 + 28 × (N-1) 天` 至 `2026-09-29 + 28 × N 天 - 1 天`，首尾都包含。
- 如果任务提前运行，只做连通性检查，不伪造正式报告，也不改变下一次报告日。

## 必须读取的四项数据

### 1. GSC 已编入索引数

数据源必须是 GSC 的“索引 > 网页”报告中“已编入索引”的原始值。

- 比较上一完整 28 天周期结束时的值与本轮 28 天周期结束时的值。
- 这是两个周期末快照，不求和、不求平均。
- 如果脚本或官方界面拿不到历史快照，写：`索引：读不到`。
- 禁止用 sitemap URL 数、抓取数、发现数、站内文章数或搜索结果数量替代。

### 2. GSC 点击

数据源必须是 GSC“效果”中的 `clicks` 原始值。

- 先确定 GSC 返回数据中的最新完整日期 `D`，不要把尚未完整的今天强行算进去。
- 本 7 天：`D-6` 至 `D`，首尾都包含。
- 上 7 天：`D-13` 至 `D-7`，首尾都包含。
- 两个区间使用相同搜索类型和相同过滤条件；默认使用全部 Web 搜索且不加页面或查询词过滤。
- 报告两个区间的点击总数，并在审计记录中保留实际日期。

### 3. GSC 平均排名

数据源必须是 GSC“效果”中的 `position` 原始值。

- 目标口径：最近完整 24 小时，对比紧邻它之前的完整 24 小时。
- 两段时间必须使用相同搜索类型、相同过滤条件和 GSC 自身的平均排名口径。
- 优先调用脚本已支持的小时级查询或 GSC 的 24 小时视图。
- 如果脚本和官方界面都不能提供小时级数据，写：`排名：读不到（无小时级数据）`。不得改成两个自然日后仍称为“24 小时”。

### 4. GA4 近 7 天日均活跃用户

数据源必须是对应 TrueDealAtlas GA4 媒体资源的 `activeUsers`。

- 使用最近 7 个完整洛杉矶自然日，不包含尚未结束的今天。
- 按 `date` 维度读取每天的 `activeUsers`，把 7 个每日值相加后除以 7。
- 保留最多两位小数；不要把“7 天去重活跃用户总数”当作“日均”。
- 无 GA4 权限、没有匹配资源或接口无法读取时，写：`GA4：读不到`。

## 本周期文章清单

1. 读取仓库的 `data/articles.json`。
2. 只选择 `published_at` 落在本轮文章周期内的记录。
3. 以 `slug` 去重，统计篇数，并列出标题和线上 URL。
4. URL 按站点规则构造；如果不能可靠构造，就只列标题与 slug，不猜 URL。
5. 不把 `data/editorial_queue.json` 中尚未发布的文章算进去。

## 输出格式

最终给机主的内容必须控制在五行以内，不添加原因分析、建议或趋势判断：

```text
第 N 轮（YYYY-MM-DD 至 YYYY-MM-DD）
索引：上期末 A -> 本期末 B
点击：上 7 天 C -> 本 7 天 D
排名：前 24 小时 E -> 最近 24 小时 F｜GA4：近 7 天日均活跃用户 G
当期文章：H 篇｜标题 1（URL）；标题 2（URL）；……
```

某项读取失败时，只替换该项，不影响其他项：

```text
索引：读不到
```

## 留档

在仓库中创建 `reports/truedealatlas-28-day-N-YYYY-MM-DD.md`，内容包括：

- 上面的五行报告；
- 每项数据的实际查询日期范围；
- GSC/GA4 资源标识（不得包含密钥）；
- 使用的脚本路径和命令，但必须删掉命令中的令牌、密钥和个人凭据；
- 读取失败项的原始错误摘要；
- 本周期文章清单。

只在本地保存报告。除非机主明确要求，否则不要提交 Git、推送 GitHub、部署网站或把报告发到其他平台。

## 永久禁止

- 不得编造、估算或外推索引数、点击数、平均排名或活跃用户。
- 不得用第三方 SEO 工具的数据替代 GSC 或 GA4。
- 不得因为缺一项而放弃其他可读取项。
- 不得解释为什么增长或下降，也不得给出改词、改方向、买外链或刷流量的建议。
- 不得修改网站、关键词、对标站、文章队列、GSC 配置或 GA4 配置。
- 不得在报告或日志中暴露任何登录凭据。

## 完成判据

只有同时满足以下条件才算完成：已按正确周期读取数据；所有数字都有 GSC、GA4 或仓库原始记录支撑；读不到的项目如实标注；五行报告已生成；本地审计文件已保存；没有执行任何发布或配置修改。
